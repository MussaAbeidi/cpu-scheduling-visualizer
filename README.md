### Project Mission and Vision

<small>Last Updated: 11/23/2026</small>

**Mission**
> Our mission is to develop a functional, interactive Python program that visualizes Various CPU scheduling algorithms such as SJF, P-SJF(SRTF), FCFS, CFS, and RR.


**Vision**
> Provide an overview of the lifecycle of a process by showing its physical movement from its inception, to being in the ready queue (if needed), to execution and termination. A goal is also to provide an interactive environment for users/students by allowing them to visualize scheduling algorithms, how multiple processes can share a single CPU, how context switching and pre-emption works.

## Development Methodology
<small>Last Updated: 11/23/2026</small>
### Always Syncing

> Before modifying any file, we will ensure that our local ```main``` is up to date with the remote repository so that we don't accidentally overwrite each other's work.

> Our GitHub repository serves as our primary project backup. By adhering to our group policies of frequently pushing local commits to GitHub, we ensure no local hardware failure will result in the loss of our project code or documentation and the project progress will proceed smoothly.

### Isolate Work

> We never commit to ```main``` directly. Instead, we will create a fresh branch for the specific task we are working on using a plain English naming scheme (Ex: ```add/CFS```).

### Meaningful Commits

> We will always push work with commit messages that tell the rest of the group *why* the change was made, rather than a simple "updated code" or no commit message at all.

### Pull Requests

> This will be done with a clear and detailed title and description. Then, we require at least one other group member to review the code changes, test them, and either approve it or deny it (with a comment in reply elaborating on why it is denied). Once approved, then it will be merged to ```main```. Finally, after it has been merged, the branch will be deleted to keep the repository clean and organized.

### AI Policy
Members can use AI for:
- Brushing up/learning concepts and syntax of Python and its libraries.
- Assisting and helping to complete a possibly lengthy test file and for brainstorming edge cases, and specific test functions.

Members <strong>cannot</strong> use AI for:
- Copy-pasting code.
- Crafting the architecture, design and logic flow of the project.
